## 2024-05-18 - Radix UI Tooltips within Repeated Lists and Tests
**Learning:** In Radix UI, wrapping every individual `Tooltip` with its own `TooltipProvider` inside a loop or mapped array breaks the global delay feature. Furthermore, when writing tests using Vitest and RTL, wrapping the components in `<TooltipProvider delayDuration={0}>` is necessary to prevent timeouts and errors. In tests, you should simulate hovering and use `waitFor` to assert on portaled tooltip elements, rather than checking for native `title` attributes.
**Action:** Always wrap lists or app roots with a single `TooltipProvider` instead of each item, include `<TooltipProvider delayDuration={0}>` in test environments rendering tooltip elements, and verify accessibility text via `userEvent.hover()` and `waitFor()`.
